# Conversation Compression & Token Tracker

Conversation compression in **RavenADK** allows agents to maintain long-running conversations without exceeding LLM context windows or incurring exorbitant API costs. 

As conversations grow, the system monitors token allocation across all components and performs intelligent compaction once the history crosses a set threshold.

---

## How It Works

The Compression Plugin operates transparently during the agent execution flow as a `before-model-call` plugin and as name tells it goes before next model call. It computes highly accurate token counts (or intelligent baselines for multimedia and file uploads) across 7 distinct context categories:

1. **`systemPrompt`**: Core behavioral guidelines and agent instructions.
2. **`thinking`**: Internal reasoning process and thoughts generated by thinking models (e.g., Gemini 2.0 Thinking, DeepSeek-R1).
3. **`userPrompt`**: The textual query typed by the user.
4. **`aiResponses`**: Text replies generated by the AI assistant, including serialized structured output.
5. **`toolCalls`**: Tool call metadata and arguments submitted by the model.
6. **`toolResponses`**: Output strings, execution results, or error traces returned from called tools.
7. **`mediaAndFiles`**: Base64 image details, audio payloads, uploaded PDFs, text documents, and video streams.

### Intelligent Compaction Strategy
When total token usage exceeds the specified percentage threshold (default: `80%` of model context window), the plugin automatically compresses historical context:
- **Preserves Core State**: Keeps the critical `system` prompt untouched.
- **Preserves Recency**: Retains the last **4 turns** completely intact to ensure the immediate thread context is pristine.
- **Reduces Bloat**:
  - Truncates older tool response logs over `400` characters.
  - Strips older heavy multimedia payloads (base64 image detail, raw audio, and files).
  - Truncates older conversational messages exceeding length limits.

## Quick Start & Usage

Below is a complete example of how to configure and integrate the compression plugin with a `ReActAgent`, subscribe to context-window event updates, and handle live token diagnostics.

```typescript
import { ReActAgent } from "@ravenlens/raven-adk/agents";
import { OpenAI } from "@ravenlens/raven-adk/models";
import { generateCompressReActAgentPlugin } from "@ravenlens/raven-adk/agents/conversation";

// 1. Initialize your LLM model wrapper
const model = new OpenAI({
    model: "gpt-4o-mini",
    apiKey: process.env.OPENAI_API_KEY
});

// A standard word-based or tokenizer model for counting tokens
// Use tokenizer compatible with your models familly e.g: `tiktoken` (BPE) for OpenAI models
const simpleTokenizer = (text: string) => text.split(/\s+/).filter(Boolean).length;

// 2. Generate the compression plugin with context listener
const compressionPlugin = generateCompressReActAgentPlugin(
    {
        name: "gpt-5.5-mini",
        contextWindowTokens: 128000 // Target model's context window limit
    },
    simpleTokenizer,
    80, // Compaction threshold (e.g. compress when context is 80% full)
    (context) => {
        // 3. Listen to context window allocations in real-time
        console.log("=== Real-time Context Metrics ===");
        console.log(`System Prompt: ${context.systemPrompt.tokens} tokens (${context.systemPrompt.percentage.toFixed(2)}%)`);
        console.log(`User Prompt: ${context.userPrompt.tokens} tokens (${context.userPrompt.percentage.toFixed(2)}%)`);
        console.log(`AI Responses: ${context.aiResponses.tokens} tokens (${context.aiResponses.percentage.toFixed(2)}%)`);
        console.log(`Tool Calls: ${context.toolCalls.tokens} tokens (${context.toolCalls.percentage.toFixed(2)}%)`);
        console.log(`Tool Responses: ${context.toolResponses.tokens} tokens (${context.toolResponses.percentage.toFixed(2)}%)`);
        console.log(`Media & Files: ${context.mediaAndFiles.tokens} tokens (${context.mediaAndFiles.percentage.toFixed(2)}%)`);
    }
);

// 4. Instantiate the ReActAgent with the compression plugin
const agent = new ReActAgent({
    model,
    systemPrompt: "You are a senior software engineer who utilizes tools accurately.",
    messages: [
        {
            type: "user",
            content: "Please help me review these log files and check for bugs."
        }
    ],
    tools: [],
    plugins: [
        // Register the compression plugin
        compressionPlugin
    ]
});

// 5. Run the agent loop
const result = await agent.invoke();
console.log("Agent result execution successfully completed.");
```

## Event Diagnostics API

The `compression_update` event outputs a structured `Context` state mapping each field category to its raw token usage and percentage:

```typescript
interface PercentageContext {
    tokens: number;      // Actual token count occupied by this field
    percentage: number;  // Usage percentage relative to total model context window
}

type Context = {
    systemPrompt: PercentageContext;
    thinking: PercentageContext;
    userPrompt: PercentageContext;
    aiResponses: PercentageContext;
    toolCalls: PercentageContext;
    toolResponses: PercentageContext;
    mediaAndFiles: PercentageContext;
};
```

This diagnostic layout makes it incredibly easy to render modern visual graphs, bar meters, or alert banners in client dashboards whenever context consumption runs high.
