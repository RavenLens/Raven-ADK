# Code Execution Sandboxes

## Overview

Raven ADK provides **Code Execution Sandboxes** to safely run arbitrary code generated by AI models. These environments provide a secure way to execute logic, perform data analysis, or run calculations without compromising the host system.

## Original Design: Supporting RLM

Sandboxes were originally designed to support the [RLM (Recurrent Language Models)](./RLMs.md) pattern. In RLM, an orchestrator model writes JavaScript code to explore and analyze large datasets. This code requires a reliable, isolated environment to:

1.  **Process Data**: Filter, aggregate, and transform large inputs that exceed context windows.
2.  **Iterative Analysis**: Run successive code blocks that maintain state across iterations.
3.  **Recursive Delegation**: Execute `llmQuery()` calls from within the code to delegate tasks to sub-models.

## Flexible Usage: ReAct Agent Tools

While built for RLM, sandboxes are modular and can be used as **standalone tools** within a [ReAct Agent](./ReAct-Agent.md). This empowers agents to:

-   Perform complex mathematical calculations.
-   Run data transformation logic on-the-fly.
-   Execute dynamic scripts retrieved from external sources.

### Example: Using Sandbox as a ReAct Tool

```typescript
import { ReActAgent } from "@ravenlens/raven-adk/agent";
import { NodeJSSandbox } from "@ravenlens/raven-adk/agent/tools/CodeExecutionSandboxes";

const sandbox = new NodeJSSandbox.NodeExecutionSandbox();

const agent = new ReActAgent({
    model: myModel,
    tools: [
        {
            name: "execute_javascript",
            description: "Run JavaScript code to perform calculations or data processing.",
            execute: async ({ code }) => {
                const result = await sandbox.execute(code, { 
                    console: { log: (msg) => console.log(msg) } 
                });
                return result.output;
            }
        }
    ]
});
```

## Available Sandboxes

### NodeExecutionSandbox
The default sandbox uses the Node.js native `vm` module to create a secure, isolated execution context.

-   **Isolation**: Uses `vm.createContext()` to prevent access to the global `process` or `require`.
-   **Async Support**: Automatically wraps code in an async IIFE to support top-level `await`.
-   **Context Injection**: Allows injecting custom data and helper functions into the sandbox environment.

## Best Practices

-   **Limit Context**: Only expose the minimum amount of data and functions necessary for the task.
-   **Monitor Logs**: Use the `logs` parameter to capture `console.log` output for agent reasoning.
-   **Timeout Handling**: Always ensure your execution environment has appropriate resource limits for your specific use case.
